# Clean Slate Protocol 🧹

## Когда применять

Этот скилл обязателен **перед** любым из следующих действий:
- Запуск новой версии демона / трейд-менеджера
- Обновление trading-скилла (patch/edit)
- Перезапуск цикла после остановки
- Любое изменение, которое может конфликтовать с работающим процессом

**НЕ применять** при:
- Обычном общении с пользователем во время активного скальпинга
- Проверке статуса демона
- Анализе рынка без перезапуска процессов

## 🚨 Исключение: обычное общение НЕ требует убивать демона

Если с пользователем идёт обычный разговор (анализ, планы, обсуждение, и даже если мы ждём сделку) — **демон ДОЛЖЕН оставаться висеть**. Не убивать его.

Clean-slate-protocol применяется ТОЛЬКО когда:
- Нужно обновить версию демона (v6 → v7)
- Нужно перезапустить цикл с новыми настройками
- Пользователь явно сказал «перезапусти демона» или «убивай всё»
- Обнаружен висящий процесс старой версии (проверить через `ps aux | grep gold_manager`)

Если демон работает и нет причин его перезапускать — **оставь его в покое**. Фоновый процесс + наш разговор = два параллельных потока.

## Протокол (4 шага)

### Шаг 1. Проверить и завершить старые процессы
### Шаг 1. Найти процессы — НО НЕ ТРОГАТЬ АКТИВНЫЙ ДЕМОН

Сначала проверить, какой PID активный (из heartbeat):
```bash
cat /c/Users/Administrator/Desktop/FxPro/.gold_heartbeat.json 2>/dev/null
```

Запомнить этот PID, НЕ убивать его. Найти все процессы и убить ТОЛЬКО неактивные.

**⚠️ Git-Bash (MINGW64) не видит python.exe из других оболочек!**
Если `ps aux | grep python` пуст, но lock-файл существует — это НЕ значит, что процесс мёртв.
Проверять через PowerShell:
```powershell
powershell -Command "Get-Process -Id $(cat /c/.../.gold_daemon.lock) -ErrorAction SilentlyContinue | Select-Object Id,ProcessName,StartTime"
```
Если процесс жив, убивать:
```powershell
powershell -Command "Stop-Process -Id $(cat /c/.../.gold_daemon.lock) -Force"
```

**ОСТОРОЖНО: kill-команды через bash могут убить всё семейство процессов:**
Когда демон запущен через bash-обёртку, kill по PID bash убивает и дочерний python.
Решение: если после clean-slate демон умер — перезапустить заново.

### Шаг 2. Очистить state-файлы

```bash
rm -f /c/Users/Administrator/Desktop/FxPro/.gold_state.json
rm -f /c/Users/Administrator/Desktop/FxPro/.gold_notify.json
rm -f /c/Users/Administrator/Desktop/FxPro/.gold_daemon.pid
rm -f /c/Users/Administrator/Desktop/FxPro/.gold_heartbeat.json
```

Проверить, что файлов нет:
```bash
ls -la /c/Users/Administrator/Desktop/FxPro/.gold_*.json /c/Users/Administrator/Desktop/FxPro/.gold_daemon.pid
```

### Шаг 3. Проверить MT5 — нет ли открытых позиций

Запросить через MT5 Python:
```python
import MetaTrader5 as mt5
mt5.initialize(path=r'C:\Users\Administrator\Desktop\FxPro\terminal64.exe', timeout=30000)
positions = mt5.positions_get(symbol='GOLD')
print(f'Open positions: {len(positions) if positions else 0}')
```

Если позиция есть и она не от текущей сессии — сообщить пользователю.

### Шаг 4. Подтвердить в чате

Написать пользователю одной строкой, что старые процессы завершены, state чист, можно запускать новую версию.

## Типовые проблемы

| Ситуация | Решение |
|----------|---------|
| Демон v6 висит, запускаю v7 | kill v6-процессы → очистить state → запустить v7 |
| PID не находится через ps (Git-Bash не видит python.exe) | Использовать `powershell Get-Process -Id <PID>` для проверки, `powershell Stop-Process -Id <PID> -Force` для убийства. `ps aux | grep python` из Git-Bash НЕ показывает процессы, запущенные из других оболочек |
| .gold_state.json остался от прошлой сессии | Удалить, иначе демон подхватит stale-данные |
| Открыта позиция с неправильным лотом | Спросить пользователя: закрыть или оставить? |
| Cron-задача висит с repeat=once | Проверить через cronjob(action='list'), удалить старую |
| kill убил и старый и новый демон (оба через bash) | Перезапустить v7 заново. В future: запускать через nohup, а не через bash-прокси |

## Важно

- **Никогда не запускай новую версию поверх работающей.** Два демона будут писать в один .gold_state.json — хаос.
- **Всегда kill → clean → start.** В этом порядке.
- **После kill проверь**, что процесс действительно умер (ps или process list).
- **Не полагайся на память** — PID мог умереть сам. Всегда проверяй через ps/list.
- **Не убивай всё подряд** — проверяй, какой именно процесс принадлежит какой версии.
- **Если kill через bash убивает всё семейство процессов** (bash-родитель + python-ребёнок) — перезапусти демона после очистки.
